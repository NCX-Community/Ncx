# Data Model: Engine Cluster Management (NCX Engine Side)

**Feature**: 001-grpc-engine-cluster
**Date**: 2026-03-02
**Contract**: `contracts/engine-cluster-stream.proto` (package `enginecluster.v1`)

---

## Proto Message Entities

### EngineRegistration (upstream — Engine → Proxy, sent once on stream open)

| Field | Type | Description |
|-------|------|-------------|
| `engine_id` | string | Unique identifier for this engine instance. Configured statically (e.g., hostname or UUID). |
| `address` | string | Engine's public network address in `"ip:port"` format. Reported to the proxy for routing. |
| `max_capacity` | int32 | Maximum number of concurrent proxy addresses (bridges) this engine can handle. Configured statically. |

**Trigger**: Sent exactly once immediately after the gRPC stream opens. Acts as the cluster registration event.

---

### EngineHeartbeat (upstream — Engine → Proxy, periodic)

| Field | Type | Description |
|-------|------|-------------|
| `engine_id` | string | Identifies the sending engine (same as used in registration). |
| `active_proxy_count` | int32 | Current number of active proxy addresses (active bridge connections) on this engine. |

**Trigger**: Sent every `heartbeat_interval` seconds while the stream is open. Allows the proxy to detect engine liveness and track current load.

---

### CapacityReport (upstream — Engine → Proxy, on demand)

| Field | Type | Description |
|-------|------|-------------|
| `engine_id` | string | Identifies the sending engine. |
| `max_capacity` | int32 | Maximum concurrent proxy addresses this engine can handle. |
| `active_proxy_count` | int32 | Current active bridge count (same as heartbeat field). |

**Trigger**: Sent in response to a `CapacityRequest` from the proxy. Contains both the declared maximum and the current load so the proxy can compute remaining available capacity.

---

### CapacityRequest (downstream — Proxy → Engine)

| Field | Type | Description |
|-------|------|-------------|
| `request_id` | string | Unique identifier for this query. Generated by the proxy. Used to correlate with the subsequent `CapacityResponse`. |

**Trigger**: Sent by the proxy when it needs real-time capacity information from the engine (e.g., before routing a new connection). The engine must respond with a `CapacityReport` upstream.

---

### CapacityResponse (downstream — Proxy → Engine)

| Field | Type | Description |
|-------|------|-------------|
| `request_id` | string | Echoes the `request_id` from the corresponding `CapacityRequest`. |
| `available_capacity` | int32 | Remaining proxy port slots this engine can still accept, as calculated by the proxy from the received `CapacityReport`. |

**Trigger**: Sent by the proxy after processing the engine's `CapacityReport` in response to a `CapacityRequest`. Informs the engine of its proxy-acknowledged remaining capacity.

---

## Capacity Query Exchange Sequence

```
Engine (C++ gRPC client)              Engine Proxy (Go gRPC server)
─────────────────────────             ──────────────────────────────
                                      [needs real-time capacity]
                            ←─────    CapacityRequest(request_id="r1")

  [read snapshot]
  CapacityReport(engine_id,
    max_capacity,
    active_proxy_count)    ─────────→

                                      [compute: max - active = available]
                            ←─────    CapacityResponse(request_id="r1",
                                        available_capacity=N)
```

**Note**: `CapacityReport` has no `request_id` field. The engine responds to any pending `CapacityRequest` with a fresh `CapacityReport`; the proxy correlates via the subsequent `CapacityResponse`.

## Internal NServer State

### EngineProxySnapshot (thread-safe in-memory struct)

Maintained by `NServer`. Updated by the EventLoop thread; read by the gRPC client thread under mutex.

| Field | Type | Description |
|-------|------|-------------|
| `active_proxy_count` | int | Sum of active bridge connections across all `SControlChannel` instances. Equals the `bridge_closers_` map size summed. |
| `mu` | std::mutex | Guards concurrent access between EventLoop (writer) and gRPC thread (reader). |

**Update triggers** (EventLoop thread):
- Bridge opened on any SControlChannel → `active_proxy_count++`
- Bridge closed on any SControlChannel → `active_proxy_count--`

---

### GrpcEngineClientConfig (parsed from `ncxs.toml`)

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `proxy_endpoint` | string | — (required) | gRPC server address of the engine proxy, `"host:port"` |
| `engine_id` | string | — (required) | Unique identifier for this engine instance |
| `engine_address` | string | — (required) | This engine's public address reported in `EngineRegistration`, `"ip:port"` |
| `max_capacity` | int | — (required) | Maximum concurrent proxy bridges this engine handles |
| `heartbeat_interval` | int | 10 | Seconds between `EngineHeartbeat` messages |

**Optional section**: If `[engine_proxy]` is absent from `ncxs.toml`, the gRPC client is not started (standalone mode, backward-compatible).

## GrpcEngineClient Lifecycle State Machine

```
              start()
                │
                ▼
         ┌─────────────┐
         │  CONNECTING │  ── dial engine proxy gRPC server
         └─────┬───────┘
               │ stream open
               ▼
         ┌──────────────────┐
         │  REGISTERING     │  ── send EngineRegistration(engine_id, address, max_capacity)
         └─────┬────────────┘
               │ registration sent
               ▼
         ┌─────────────────────────────────────────────────────┐
         │                 STREAMING (main loop)                │
         │                                                      │
         │  Write thread (timer, every heartbeat_interval s):  │
         │    read snapshot.active_proxy_count (under mutex)   │
         │    send EngineHeartbeat(engine_id, active_count)    │
         │                                                      │
         │  Read thread (blocking stream->Read()):             │
         │    on CapacityRequest:                              │
         │      read snapshot.active_proxy_count (under mutex) │
         │      send CapacityReport(engine_id, max, active)   │
         │    on CapacityResponse:                             │
         │      log available_capacity (no action required)   │
         └─────┬───────────────────────────────────────────────┘
               │ stream error / server close
               ▼
         ┌─────────────┐
         │  RECONNECT  │  ── wait 5 s, retry CONNECTING
         └─────────────┘
               │ stop() called
               ▼
         ┌─────────────┐
         │   STOPPED   │
         └─────────────┘
```
